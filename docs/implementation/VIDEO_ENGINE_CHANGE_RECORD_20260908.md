# Change Record — Daily Line Social Video Engine Architecture

Timestamp: **2026-09-08T07:32:00Z**  
Local date: **2026-09-08 America/Los_Angeles**

- **Change ID:** DLVE-V1 architecture pass / ADR-0008.
- **Area:** architecture / documentation / content publication / rendering / assets / analytics / experimentation.
- **Summary:** Added a complete supplemental architecture baseline for The Daily Line Social Video Engine (DLVE) inside `The-Daily-Line-Automation`. The architecture defines the sport-fact boundary, versioned fact/video contracts, Remotion-based replaceable renderer model, reusable Daily Line brand/title-card system, seven initial video template families, asset provenance and generated-still strategy, voice/caption/audio contracts, render/QC/publication-package handoff, performance metric normalization, controlled creative experimentation, and an implementation roadmap from schema fixtures through future adaptive creative selection.
- **Reason:** The Daily Line needs a scalable social-video system for MLB/NFL/NCAAF and future sports that can generate consistent branded videos cheaply from data graphics, reusable motion, generated/stock stills, voice/captions, and reusable templates. The design must preserve TDLA's existing rule that sport truth remains in sport repositories and must avoid building an un-auditable LLM or proprietary-video workflow.
- **Files/components affected:** `docs/video/README.md`; `docs/video/V00_SOCIAL_VIDEO_ENGINE_ARCHITECTURE_V1.md`; `docs/video/V01_VIDEO_JOB_AND_FACT_CONTRACTS_V1.md`; `docs/video/V02_BRAND_MOTION_SYSTEM_V1.md`; `docs/video/V03_TEMPLATE_LIBRARY_V1.md`; `docs/video/V04_RENDER_ASSET_QC_HANDOFF_V1.md`; `docs/video/V05_PERFORMANCE_EXPERIMENTATION_V1.md`; `docs/implementation/VIDEO_ENGINE_IMPLEMENTATION_ROADMAP_V1.md`; `docs/implementation/VIDEO_ENGINE_ARCHITECTURE_CONFORMANCE_REVIEW_20260908.md`; `docs/adr/ADR-0008_PARAMETERIZED_VIDEO_RENDERER_AND_FACT_AUTHORITY.md`; `docs/implementation/CURRENT_RESUME_POINT.md` is synchronized separately.
- **Authority/contract impact:** Establishes the V-series as a supplemental DLVE V1 architecture baseline. Sport repositories remain authoritative for sport facts, predictions, recommendations, causal interpretation, and explanation claims. DLVE may perform presentation transformation only over approved `PublishableFactPackage` content. Remotion is the initial renderer but not canonical identity authority. V-series publication scope ends at `VideoPublicationPackage`; A-18 remains authoritative for external social-platform side effects. A-11/A-13/A-15/A-20/A-24 deferred authority is explicitly preserved.
- **Data/migration impact:** None. No runtime database schema, migration, object-storage bucket, contract implementation, or generated media was created. Canonical schemas are architectural definitions only until VM-0 implements them.
- **Operational impact:** None in production. No social accounts are connected or posted to. No image-generation, TTS, stock, platform, or analytics provider is made authoritative. No render worker is deployed. The architecture permits local/shadow development through synthetic fixtures without external side effects.
- **Validation/evidence:** `VIDEO_ENGINE_ARCHITECTURE_CONFORMANCE_REVIEW_20260908.md` checks 48 authority/fact/identity/render/fallback/brand/publication/performance scenarios and verifies compatibility with the certified A-0 through A-10 architecture. Review result: PASS for the supplemental V1 baseline, with deferred A-series boundaries left intact.
- **Risks/open questions:** Exact production font/audio identity; provider selection for generated images/TTS/stock; A-11 retry key mechanics; A-13 DDL/retention; A-15 resource budgets; A-18 platform APIs and publication idempotency; A-20 service identities/secrets; platform/jurisdiction-specific compliance rules; A-24 adaptive-selection authority. None may be silently guessed during implementation.
- **Rollback/recovery:** Documentation-only architecture. If the V1 subsystem is superseded, retain these files/history and create a versioned V2/addendum/ADR with compatibility notes. Existing future render artifacts must retain the exact V1 schema/template/brand/renderer provenance they used.
- **Next exact step:** Core TDLA architecture remains **A-11 Retry / Timeout / Idempotency**. When the video subsystem is intentionally implemented, begin with **VM-0 — canonical JSON Schemas and cross-language fixtures**, then VM-1 Remotion scaffold, VM-2 brand/title sting, VM-3 shared components, and VM-4 synthetic `single_pick_v1`. External posting remains blocked until A-18.
